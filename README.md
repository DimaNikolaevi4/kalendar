# Календарь — общий план по всем репозиториям `E:\github`

Один файл `PLAN.md` отвечает на вопросы «что нужно делать, когда и зачем»
по всем проектам. Собирается автоматически, задача Планировщика Windows
«Календарь build plan» — ежедневно в **07:25 МСК** (сборка + коммит + пуш).

## Модель: репозитории «скидывают» планы в хаб

1. **Источник истины** — `plan.json` в корне каждого репозитория
   (хранится в git самого репо, правится автоматикой или агентом/владельцем).
2. **Авто-скидывание** — сборка (`build_plan.py`) перед рендером сама делает
   `drop.py <REPO> --no-push` для всех репо из `participants.txt`. Вручную
   ничего скидывать не нужно (но можно: `python drop.py <REPO>`).
3. **Сборка** — `build_plan.py` рендерит `plans/*.json` в `PLAN.md`:
   Просрочено → Сегодня → На неделю → Запланировано → Backlog → Сводка
   (в сводке видно, когда какой репо последний обновлял план).

## Схема задачи в `plan.json`

```json
{
  "tasks": [
    {"id": "уникальный-ид", "title": "Что сделать",
     "when": "2026-11-24", "time": null, "status": "todo",
     "why": "зачем — одна фраза", "link": "путь-к-детаям.md",
     "source": "owner"}
  ]
}
```

| Поле | Значение |
|---|---|
| `when` | дата `YYYY-MM-DD` или пусто (тогда задача в Backlog) |
| `status` | `scheduled` (автомат доведёт до done) · `todo` · `in-progress` · `done` · `skipped` · `backlog` |
| `why` | зачем — одно предложение, почему это важно |
| `source` | `owner` (решение владельца) · `agent` (предложение агента) · `auto` (автоматика) |

Просроченным считается `todo`/`in-progress`/`scheduled` с датой в прошлом —
такие задачи поднимаются в секцию «Просрочено» с пометкой возраста.

## Ручные команды

```powershell
py E:\github\Календарь\build_plan.py        # drop всех участников + пересборка PLAN.md
py E:\github\Календарь\build_plan.py --push # то же + коммит + пуш
py E:\github\Календарь\build_plan.py --no-drop --push # пересборка без обновления планов
py E:\github\Календарь\drop.py MAX          # скинуть план одного репо (с пушем)
```
