# Синхронизация / оркестрация (команда «прочти E:\github\kalendar и все синхронизируй»)

Этот файл — рабочий протокол для агента, когда владелец просит: **«прочти E:\github\kalendar и все синхронизируй»**.

## 1. Что сделать

1. Прочитать контекст хаба: `E:\github\kalendar\README.md`, `PLAN.md`, `participants.txt`, этот файл.
2. Обновить план MAX в хабе (минимум):  
   `py E:\github\kalendar\drop.py MAX --no-push`  
   (при необходимости полной пересборки — `py E:\github\kalendar\build_plan.py --no-drop` без `--push`, пуш — по отдельному решению).
3. Прочитать служебную команду/состояние catden в MAX:
   - `E:\github\MAX\roles\blogger\config\catden-automation.json` (источник оркестрации, переживает регенерацию `plan.json`);
   - при наличии — задачи `source: kalendar`/`orch-*` в `E:\github\kalendar\plans\MAX.json` (и в `E:\github\MAX\plan.json`).
4. Запустить отчёт оркестратора:  
   `py E:\github\kalendar\sync.py`  
   (МСК-дата/день недели определяются автоматически; для проверки: `--date YYYY-MM-DD`, `--force thu|fri`).
5. Выполнить действия по дню недели (МСК) и доложить владельцу: **что опубликовано/отправлено в канал «календарь»** или **явные поломки/ограничения**.

## 2. Четверг — медиа на хостинг (окно 11 дней)

- Источник истины: front matter постов catden (`image_file` / `image_files`) и расписание/манифест в MAX (`local/catden-v1-schedule.json`, `docs/catden-media-manifest-*.md`).
- Хостинг: `/0s3/blogger-data/media/catden/<дата>/`.
- Действия: сверить уже загруженное (без дублей/пропусков) → догрузить недостающее на 11 дней вперёд → удалить отработавшее после публикации.
- Если нет доступа к хостингу/оригиналам (`nev/posting/images` локально может отсутствовать): **не скрывать проблему**, выдать точный список дат/файлов и пометку «требуется доступ к хостингу/хранилищу».

## 3. Пятница — агентный прогон + превью 10 дней в «календарь»

- Окно: ближайшие 10 дней в порядке публикации.
- **Подготовка до отправки (обязательно):** стилистическая шлифовка через ИИ (агент, `roles/blogger/channels/catden/style.md`: факты/смысл/CTA/ссылки не искажать, без «воды»/выдумок, объём до 4000, 3500–4000 где уместно, интервалы по правилу) + **слои 1–3** на тексте кандидата **до отправки**:
  - **Слой 1 (блокирующий):** LanguageTool (как в `publish_post.py`, §5а+ AGENTS.md MAX). Блокеры устранять до отправки.
  - **Слой 2 (WARN):** `shared.readability` — по возможности править.
  - **Слой 3 (WARN):** `shared.lexicon` (ru-humanizer при наличии) с учётом канальных исключений.
  - **Слой 4:** вычитка владельца в «календаре»; без правок → публикация по графику, правки → агент синхронизирует в файлы/статусы/медиа.
- **Превью в канал «календарь»:** текст + медиа **как будет публиковаться, без дат**. Медиа — **с хостинга** (залиты в четверг). `draft` — с явной пометкой (медиа/approved не готовы).
  - Отправка: MAX `POST /messages?chat_id=...` (`calendar` в `E:\github\MAX\local\tokens.json`), `format: markdown`, **без `notify`**.
  - Если медиа с хостинга недоступно для вложения — отправлять текст с явной пометкой источника/ожидания медиа с хостинга, не блокируя вычитку текста (и отразить в отчёте).
- `sync.py --send-preview` отправляет **текстовые** превью (без вложений медиа с хостинга) — использовать только после прохождения слоёв 1-3 и стилистики агентом для кандидатов.

## 4. Отчётность

- Владельцу сообщать по итогу sync: что отправлено в «календарь» (даты/сообщения/mid) или явные поломки; отдельно — ограничения среды.
- Операционный статус catden и zabava (обе на автопубликации хостинга): **«автопубликация готова на N дней»** — сколько дней вперёд готовы approved-посты с медиа на FTP. Границы `ready_until`/`ready_days` ведутся в `automation.json` канала (catden: `E:\github\MAX\roles\blogger\config\catden-automation.json`, zabava: `...\zabava-automation.json`). Если пост вышел на автомате: «<дата> пост вышел на автомате». Старая форма «посты до <дата> готовы» больше не используется.
- Авто-файлы вроде `docs/blogger-calendar.md` руками не править; `PLAN.md` в хабе — продукт сборки.

## 5. Важные проверки

- **Сегодня 20:00 МСК (catden):** публикация берёт `approved`-посты канала с датой из имени файла ≤ сегодня и без `message_id` (`publish_scheduled.py`/хостинг). Если файла `YYYY-MM-DD-*.md` на сегодня нет в `posts/` — в 20:00 публиковать нечего (вхолостую), даже если ранее в этот день уже выходил пост другим слотом/вручную.
- Перед любыми коммитами — чек-лист безопасности из `E:\github\kalendar\README.md` (без `git add -A`, проверить `diff --cached --stat` на неожиданные удаления). Пуш — по договорённости.
- Токены/доступы — только из локальных gitignored источников.
